# Building the Swirl client

- `tools/build-client.sh [outdir]` builds `swirl-client` for wasm32 with the `client` profile (opt-level 2, no LTO, 16 codegen units, incremental, panic abort), runs `wasm-bindgen --target web` and writes `entry.js` and `manifest.json` ({version "N.M", era, entry, build hash}) next to the wasm. Default output `/var/www/swirl/dist/client`. `PROFILE=client-size` gives a smaller thin-LTO build; `WASM_OPT=1` runs `wasm-opt -O1` when it is installed.
- `tools/release-client.sh` builds, records the release without making it current, runs `tools/browser-check.cjs` (headless Chromium logs in as the test account, opens `/play/<place>?swirl=<version>`, fails on page errors, a shown fatal overlay or a blank canvas, screenshot in `/tmp/swirl/release-<version>.png`) and and a walk and jump test (`WALK=1`, reads `window.solarClient.own_pos()`) and only then, with `CURRENT=1`, runs `release.php current developer <version>`. `NOTES="..."` sets the notes; `CHECK_PLACE` changes the place. `/play/{id}?swirl=<version>` previews any developer release for Role 3 users; `release.php clear developer` takes the channel back to Chocolate. Releases are N.M (1.0, 1.1, ...) taken from the crate version; bump `crates/swirl-client/Cargo.toml` (and the other crates) for a new minor.
- The entry runs as soon as it is imported when `window.solarClientConfig` exists, uses `#swirl-canvas` and `#swirl-status`, requests the ticket like Chocolate's client, joins `<ws>?ticket=`, calls `window.solarClientReady()` when the snapshot is drawn and `window.solarClientFailed(reason)` on errors.
- Tests without a browser: `wasm-bindgen --target nodejs --out-dir /tmp/swirl/wnode target/wasm32-unknown-unknown/client/swirl_client.wasm`, then `node tools/wasm-load-test.cjs /tmp/swirl/wnode <init.json>` or start `swirl-server --place=ID --port=<spare>` and run `node tools/wasm-join-test.cjs /tmp/swirl/wnode <port>`. WebGL drawing cannot be checked on the server.
- Keep the client crate small: protocol and world logic live in `swirl-net` (native tests), GL glue in `swirl-client`. Debug builds: workspace `dev` profile is opt-level 1 with dependencies at opt-level 2; rust's own lld linker is the default on this toolchain.

Measured on this box (4 cores): clean wasm build 27 s (client profile), 34 s for `client-size`; one-line edit in swirl-client or swirl-net 0.9 s, in swirl-core 1.8 s, no-op 0.3 s (cargo plus wasm-bindgen).

- Local checks without Solar or the live server: build to a scratch dir (`tools/build-client.sh /tmp/swirl/dist113`), start `swirl-server --place=1669 --port=N` (add `--site=http://127.0.0.1` for avatars with clothes and hats), then `DIST=/tmp/swirl/dist113 node tools/swirl-local-test.cjs N /tmp/swirl/prefix` (two headless pages: hotbar equip, a click, chat; `SCENARIO=look` for a character screenshot). Release 1.13 added tools, chat, clothing and the head mesh to the client; the release gate still only walks and loads meshes on the live server.

- Client Lua (1.15): `entry.js` imports `./lua.js` (copied by `build-client.sh`), which loads Chocolate's engine from the public path and exposes `window.solarLua` (`world`, `gui`, `errors` for CoreScript Lua errors, `gameErrors`, `logs`, `ready()`). The wasm `Client` has `take_tap()` (every raw server message) and `camera_pose()`. A local page needs `/chocolate/` and `/asset` proxied to the site (see `tools/swirl-gui-test.cjs`, which does that). `swirl-server --chocolate=DIR` supplies the Health scripts and the 2018 core bundle. Local GUI check: start `swirl-server --place=1669 --port=N --site=http://127.0.0.1` (add `--era=2018 --place=3` for 2018), then `DIST=<dist> CHAT=hello node tools/swirl-gui-test.cjs N /tmp/swirl/gui`; screenshots `<prefix>-1.png`, `-chat.png`, `-click.png`. The release gate (`tools/browser-check.cjs`) fails when the player list or hotbar/topbar is missing or a CoreScript Lua error is logged.
